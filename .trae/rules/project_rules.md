# Karpathy Coding Guidelines

每次修改或生成代码时，必须严格遵循以下 Karpathy 编程准则：

## 1. 先思考再编码（Think Before Coding）
- 明确陈述假设，不确定时先提问
- 存在多种解释时，全部列出而非默默选择
- 存在更简单的方案时，提出并反对过度设计
- 不清楚时停下来，指出疑惑并提问

## 2. 简洁至上（Simplicity First）
- 只实现被要求的特性，不做多余功能
- 不要为单次使用的代码创建抽象
- 不要添加未被要求的"灵活性"或"可配置性"
- 不要处理不可能发生的错误场景
- 如果写了200行但能用50行解决，重写

## 3. 精确修改（Surgical Changes）
- 只修改必须修改的部分
- 不要"改进"相邻代码、注释或格式
- 不要重构未损坏的代码
- 匹配现有代码风格
- 如果修改产生了未使用的导入/变量/函数，清理它们

## 4. 目标驱动执行（Goal-Driven Execution）
- 将任务转化为可验证的目标
- 多步骤任务需列出计划并验证每一步
- 明确成功标准
